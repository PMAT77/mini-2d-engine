# Mini 2D Engine

基于 TypeScript、Vite 和 Canvas 2D 的俯视角战术生存 Roguelite 原型：在黑暗的站点里探索、搜刮，用光、地形和声音与敌人周旋，最后带着战利品撤离。玩法骨架见 [游戏设计](docs/game-design.md)，开发顺序见 [开发路线图](docs/roadmap.md)。

当前是可玩的引擎演示，包含随机瓦片地图、碰撞移动、可破坏矿石、换弹与装填、主副武器切换、道具增益、粒子与动态地块投影；屏幕右下角的武器卡片显示当前武器、弹药与手电开关状态。尚未提供敌人 AI、背包、撤离与存档。

## 运行与验证

```bash
npm ci
npm run dev
```

按 Enter 开始，WASD 移动，鼠标左键单发／按住连射，按住右键瞄准（身体转向鼠标；准星压住活鸡时变红并收紧），按住任意 Shift 疾跑，空格翻滚（消耗体力），Q／E 切换主副武器，C 收起枪械／空手，G 开关手电筒，R 换弹／装填（默认方式可在 F2 面板切换）。生命条和青蓝色体力条常驻角色下方，换弹进度圆环位于角色右上角，只在换弹期间显示。屏幕右下角常驻武器卡片，显示图标、槽位（主／副）、武器名、`弹匣/容量`、逐发弹槽、膛内一发与备弹；卡片上方是手电开关胶囊。

人物为 Canvas 绘制的俯视圆柱小人，可见浅色头顶、蓝青色身体和双臂，不需要加载头像图片。白色十字准星跟随鼠标，中心点始终为白色且不受后坐力或相机震动影响；准星压住活鸡时四臂变为红色。准星是独立的 DOM 图层，位置在鼠标事件里直接写入，不等世界渲染帧，所以帧率再低也不拖影。进入对局后系统鼠标指针被隐藏（页面级，只剩准星），F2 调试面板的按钮仍保留可点击指针；离开对局自动恢复。未瞄准时准星间隙为 6 像素，按住右键且准星压住活鸡时约 0.2 秒内收紧到 2 像素，移开目标或松开右键后回弹。右键按住时约 100 毫秒抬起双臂，身体按原有转身速度和策略追随鼠标；左键仍可独立开火，开火首帧立即抬臂，不改变身体朝向。松键后手臂放下，身体恢复移动朝向。子弹从右手末端飞向发射瞬间确定的落点；贴墙时先检查身体到右手的路径，不能越墙出生。落点带水平、垂直随机散布，连射扩大散布、停火后恢复，后坐力仍会在此基础上追加最多 8 像素的准星间距。子弹到达落点、从手端飞满最大射程（默认 1000 世界像素／20 格）或撞到第一个障碍时销毁，不追踪后续鼠标位置。子弹是白色细线，长度取当帧实际位移、最短 6 像素；命中墙壁、矿石或水面时扬起白灰色烟尘。子弹在干燥地面自然落地（到达落点或射满射程）时会留下直径 6～10 像素、深浅随机的圆形或不规则弹坑，完整保留 3 秒后用约 0.8 秒淡出；弹坑只用柔和的暗色斑块表现，不描亮边；落点在水面、墙壁、矿石或地图外时不生成。弹坑只绘制在地形层，不参与碰撞，贴墙或贴岸线时会缩小到完全落在干燥地面内。方向键不再射击。参数见 [CONFIGURATION.md](public/configs/CONFIGURATION.md)。

视野是面朝方向的锥形手电筒，默认张角 120°、视距 400 世界像素，亮度低、边缘柔和；三个数都可改 `graphicsConfig.json` 的 `flashlight` 分组，或在画面 Tab 实时调整。右键只改变身体朝向（准星变红与收紧只是视觉反馈，不改变子弹散布），不改变视野远近或角度。地形（含墙壁与矿石顶面）始终可见，只受环境光和左上方向的地形弱光影响，不被视野或单位光压暗，也不会被任何投影盖住；环境光强度默认 0.35。单位光只照亮地面和水域，墙顶不会被手电筒或火把“爬”亮。战争迷雾是以角色为中心、默认半径 400 的柔边圆形遮罩：地形在迷雾外仍然可见，但掉落物、拾取物、子弹、粒子（以及以后的敌人）只有进入迷雾范围才绘制。G 键开／关手电筒，开关状态同步显示在右下角武器卡上方的胶囊里；脚边另有一圈默认半径 100、强度 0.5 的小范围全向微光，数值见 `graphicsConfig.json`，可在画面 Tab 调整。

运行 `npm run test:visibility-browser` 验收固定视野、地形不被迷雾压暗、单位只受迷雾裁剪、手电筒锥光与 G 开关、朝向跟随身体，以及 DPR 1／1.25／2、相机震动和缩放。截图与像素采样保存在 `.review/fog-flashlight-dpr*.png` 和 `.review/fog-pixels.json`。

已有 Playwright 环境时，运行 `npm run test:shooting-browser` 检查真实鼠标单击／连射、右键转身、输入清理、墙体阻挡和落点截断，并在 DPR 1／1.25／2 下验证缩放、相机震动、准星坐标／配色与瞄准收缩。单元测试同时覆盖 30／60／144 FPS 的旋转和散布恢复。截图与采样结果保存至 `.review/`，浏览器环境变量与下述验收命令一致。

运行 `npm run test:weapon-hud-browser` 验收右下角武器卡片与手电胶囊：在 DPR 1／1.25／2 下检查卡片锚点与边距、手枪 `6/6` 时最右弹槽的暖黄像素、空仓变暗与文案、换弹时逐槽填充、装填时逐发亮起、冲锋枪 `30/30` 的连续容量条、C 空手后的紧凑卡片、G 开关手电的状态灯、按 F2 打开居中调试弹窗再关闭后 HUD 仍正常绘制、R 键默认行为切到装填后的逐发动画，以及两把枪的枪声文件可访问。逻辑测试同时覆盖布局、状态机与绘制文案。截图保存至 `.review/weapon-hud-*.png`。

移动从静止起步，80 毫秒内以 smoothstep 曲线平滑加速至满速，起止加速度均为 0；转向带 12 毫秒轻微阻尼，反向立即响应。松键后以 smoothstep 曲线减速收尾，时长不超过本次连续按键时长、最多 200 毫秒：短按用于微调位置，持续移动后常速满速收尾额外滑行约 20 像素。重新输入立即接管，收尾期间不消耗体力。基础移速为 200 像素/秒，按 Shift 后用 160 毫秒平滑升至 1.6 倍疾跑速度，继续受到地形及移速道具影响，疾跑时可以正常射击。可将 `movement.turnDamping` 调为 0 恢复即时转向，将 `movement.stopDuration` 调为 0 恢复松键即停。

人物在有移动输入且实际前进时，每 26 世界像素沿行进方向、在身体左右两侧交替留下白色脚印；每枚脚印先保持清晰，再从寿命的 35% 处开始平滑淡出，干燥地面总寿命约 2.4 秒，不参与碰撞、拾取、挡光或子弹。身体接触任何水深时持续刷新涉水湿度，离水后的 1.5 秒内生成的脚印会按最近接触的最大水深加深：不透明度从 55% 提高到最高 95%，脚印最多放大 15%，寿命从 2.4 秒延长到最多约 6 秒；浅水提升较小，深水最明显。水中、墙壁、矿石、地图外以及静止或被墙挡住时不绘制脚印。涉水时这些脚印改为水面涟漪：只在整圈都落在水面内的步点出现，圆心随寿命沿行进反方向漂移，只画朝后的弧线，从 3 像素按水深扩散到 9–19.5 像素，0.5–0.74 秒内淡出，用浅青色描边；出水后的湿脚印保持上面的加深与延长。涉水行走的音效按整段采样循环播放：身体接触水面且这一帧确实在移动时淡入，播放速率随实际速度在 0.6–1.6 倍之间伸缩，停下、离水或被墙挡住时在 120 毫秒内淡出；水中不再逐个脚步重放，循环不会被截成碎片。脚印与涟漪属于地面装饰，绘制在地形之后、弹坑之下，始终可见并随世界光照变暗，不进入战争迷雾单位层。

人物贴住地图边界并继续朝界外推时，接触边会连续浮出暖色涟漪，提示“这里有阻挡”而不是普通脚步：圆心落在边界线上，弧线朝地图内侧展开、越界一侧留空，外圈带一点暖光；同一处接触约每 0.18 秒补一圈，半径从约 12 世界像素扩散到 40 像素并在 0.5 秒内淡出，转身离开或松开方向键后不再生成。边界反馈画在光照之后，暗处也不会被乘暗，玩家血条与体力条仍压在最上层。地图之外只保留稀疏的文字水印：界外底色与地图完全一致，不叠色、不描边，只平铺轻微倾斜、间距更大的“无法通行”文字；水印仅绘制在世界画布内、位于角色界面元素之下，不参与碰撞、拾取、挡光或战争迷雾。

体力上限 100，疾跑每秒消耗 25，连续可跑 4 秒；停止消耗 0.6 秒后每秒恢复 35。静止或完全顶墙不消耗，滑墙移动正常消耗。耗尽后回到常速，必须松开过 Shift 且恢复至少 15% 才能再次疾跑。耗尽锁定时体力条变暗并显示橙色边框，仍可正常移动与射击。

空格向当前移动方向翻滚，没有移动输入时朝身体正面；方向在起滚瞬间锁定。动作 0.3 秒、峰值 3 倍基础移速，总位移约 120 像素，途中照常受碰撞与地形减速。起滚立即扣除 20 点体力并打断疾跑，把体力恢复延迟重置为 0.6 秒，动作期间不恢复体力；体力不足 20 时按空格无效。动作加 0.4 秒冷却内不能再次翻滚，满体力可连滚 5 次。翻滚期间不能开火、不抬枪、不生成脚印；换弹与切枪照常，动画只做绕身体左右轴的前后翻与收身，只影响绘制。动作结束不保留滑行惯性。参数见 [CONFIGURATION.md](public/configs/CONFIGURATION.md) 的 `roll` 分组。

初始装备为主武器冲锋枪与副武器格洛克手枪，默认手持格洛克手枪。Q／E 在主副武器间切换，从空手状态按 Q／E 会先拔出上一把枪；C 收起枪械切换为空手，再按 C 或 Q／E 拔枪。两把枪各自保留弹匣、膛内与换弹进度：换弹中切走，进度留在原来那把枪上。副武器格洛克手枪弹匣 6 发加膛内 1 发，换弹 1.4 秒，单发伤害 10；主武器冲锋枪弹匣 30 发加膛内 1 发，射速约每秒 13.3 发、单发伤害 16、弹速 2800 像素/秒，换弹 2 秒，并使用独立的冲锋枪枪声。两把枪的开火声都取自 [public/audio/weapons](public/audio/weapons) 的现代手枪音效库：格洛克用 `Fire/01_Pistol_Type1_Fire.wav`，冲锋枪用 `Fire/05_Pistol_Type5_Fire.wav`；两段都是单发采样，每发跳过录音开头的静音预卷起播，不再按弹匣余量往采样深处跳。换弹声同样出自该库：格洛克用 `Reload/Type_1/Pistol_Reload_Type_1_Full.wav`，冲锋枪用 `Reload/Type_5/Pistol_Reload_Type_5_Full.wav`；两段都是约 4 秒的完整换弹，按 2 倍速播放，才能在 1.4／2 秒的动作里听全退弹匣、插弹匣、拉套筒，换弹结束或被开火打断时提前淡出，不会盖住下一声枪响。调试阶段备弹仍然无限，打空后不会自动换弹，需要按 R 换弹；调试面板的“打空自动换弹”开关默认关闭。换弹中开火会打断换弹、清空进度，需要重新按 R。R 键默认执行换弹：直接丢弃整个弹匣再重装，哪怕匣里还剩不少子弹；F2 面板的“R 键行为”可以改成装填：保留当前弹匣余弹、只补缺失的子弹，耗时按缺弹数缩放（每发约 1.5／容量倍换弹时长，最低 0.35 秒）。装填沿用同一段换弹采样。未拿在手上的枪分别斜挎在背上、挂在右腰；切换时手臂与枪口短暂下沉再抬起，只是视觉动作，不影响射击判定。换弹进度圆环从顶部顺时针填充，换弹结束后淡出。

屏幕右下角的武器卡片实时反映这些状态：336×132 的卡片包含武器图标、槽位胶囊（主／副）、武器名、`弹匣余弹/容量` 大号数字、逐发弹匣槽（最右一格紧贴独立的膛内槽）和膛内槽；开火从最右侧开始熄灭，余弹降到总容量四分之一时数字转橙，打空转红并提示 `R 换弹`；换弹时旧弹匣先下沉淡出，弹槽自左向右填琥珀，右上角显示 `换弹中`，完成瞬间暖闪一次；装填时原有子弹保持亮起，新子弹从缺口处逐发填入并带白色落座闪光，右上角显示 `装填中`，时长随缺弹数变化。备弹无限时右上角显示 `备弹 ∞`，武器名下方提示 Q／E／C 操作；弹匣容量超过 10 发时改用连续容量条（冲锋枪 30 发即为此形态）。空手时卡片收成 92 像素高，不显示弹药。卡片上方的胶囊显示手电开／关与 G 键提示，开灯时呈琥珀色。

## 代码结构

进入游戏后点击右上角“调试 · F2”或按 F2，打开居中的调试弹窗；内部按“角色／画面／音效”分三页。角色页可实时修改血量、攻击力、射速、弹匣与换弹（含“打空自动换弹”开关与“R 键行为”下拉，默认关闭／换弹）、移动手感、体力、翻滚、体型与动画、水体阻力、界面反馈；画面页可调相机缩放、环境光、地形光、角色微光、手电筒距离／张角／强度与战争迷雾；音效页可调总音量与各类音效音量。攻击与弹药字段跟随当前手持的枪，空手时回落到上一把枪。每个数值项同时提供可拖动滑条与精确数值框：拖动滑条即时生效，数值框按回车或失焦应用。Escape、遮罩或“关闭”按钮收起，点击游戏画面恢复键盘控制；面板关闭时按 Escape 可唤出／收起系统鼠标，唤出时准星与瞄准暂停。改动仅本次运行生效；“恢复初始参数”还原角色／画面／音效三份配置、回满资源并保留道具增益。面板打开时角色输入被屏蔽，且不再为 HUD 让位。完整字段见 [配置参考](public/configs/CONFIGURATION.md)。启动开发服务后，运行 `npm run test:debug-browser` 验证弹窗、Tab 切换与输入隔离，浏览器环境变量同下方其他验收命令。

- `src/core`：游戏循环、场景、输入、相机、资源和配置加载、光照、锥形手电筒、战争迷雾、增益管理。
- `src/map`：随机地形、通行判断、瓦片伤害、投影边界与地图外文字水印。
- `src/physics`：形状编译、精确碰撞、覆盖面积、连续检测和运动约束。
- `src/objects`：玩家、子弹、道具、粒子、地面弹坑、脚印及水面涟漪、贴边阻挡波纹、武器挂载绘制，以及武器只读视图数据。
- `src/scenes`：菜单、真实资源加载和游戏场景。
- `src/status`：待机、移动和射击状态。
- `src/ui`：右下角武器 HUD、手电开关胶囊与角色属性调试面板。

## 碰撞与地形缓速

墙壁、黄金矿和特殊矿按相邻关系融合为连续地形，外凸角与内凹角均采用圆角，半径为地块尺寸的 30%（默认 15 像素）；仅共边连接，斜对角保持分离。异类连接保留各自颜色与图标，内凹补圆沿角平分线归属相邻两块。绘制、角色／子弹碰撞、地形覆盖与投影共用轮廓，矿石破坏后立即更新。运行 `npm run test:rounded-terrain-browser` 检查圆角、接缝、水面遮挡及 DPR／相机偏移，截图保存至 `.review/rounded-terrain-dpr*.png`。

地面、墙顶和矿石底色按 16×16 瓦片分块烘焙到离屏画布，带 1 格外扩，块内一次 `solidPath` 合并填充；相邻块按整数画布像素贴回，接缝与逐格绘制一致。每帧对块内外各格 `tiles` 做一次内容哈希，直接改数组（测试和挖矿都这么做）会在同一帧重烘焙，只有相机移动不会。受击高亮、矿块破损色块和矿种图标仍逐帧绘制在缓存之上，保持原有精度；`tileSize` 变化时整块缓存重置。块数按可见数量加 2 淘汰，避免在大视口下每帧来回烘焙。没有 `document` 的环境（Node 单测）回退到原来的逐格绘制路径。

玩家主体固定为居中的圆形，默认直径 49 像素、半径 24.5 像素。移动、转向、地形缓速、拾取和出生校验只读取这个圆；圆柱外观、伸出的手臂及呼吸缩放只参与绘制，不改变通行能力。窄通道内可以转向、反向返回，沿墙及墙角移动保留切向速度。

通用实体仍支持圆形、凸／凹多边形和复合形状。方形等非圆实体贴墙旋转时会因伸出的角逐渐挤离墙面，空间不足时停转；玩家不采用这类外观轮廓作为碰撞体。

地图生成少量成片湖泊，按浅水、中水、深水、超深水分为四档，移速系数分别为 0.75、0.5、0.25、0。水深由岸边向内部逐级加深，四档采用由浅青蓝到暗蓝的颜色，不规则闭合边界有约 4 像素柔和过渡。超深水阻止角色和地面掉落物进入，所有水深均允许子弹与光线越过。

角色开火时身体与水体有实际重叠，该颗子弹启用持续水体阻力；水外开火的子弹经过任何水深均保持正常速度。阻力资格和各水深减速参数在发射时固定，之后只按子弹圆形与各水深的实际覆盖比例计算线性减速度：浅水、中水、深水、超深水每秒分别扣除发射速度的 40%、80%、160%、320%，默认强度约为原来的一半。完全处于单一水深时，从原速到停止分别需 2.5、1.25、0.625、0.3125 秒；停止位置散出 4 颗约 0.22 秒淡出的细小白色湮灭粒子后消失，不造成伤害。跨水深时累积减速，离水保持剩余速度，再次入水继续减速；弹速增益计入发射速度。子弹按最多 1/120 秒且最多 1 像素的步长积分，沿实际位移检测首次命中。

调试弹窗“子弹水体阻力”可分别修改四档“减速 %/秒”，设为 0 关闭对应水深的阻力，修改影响后续发射的子弹。“恢复初始参数”同时还原四项；配置文件对应 `bulletWaterDrag` 分组，使用每秒比例（界面 40 对应配置 0.4）。

子弹与角色共用水体颜色遮罩规则：只在圆形与水面重叠的部分叠加 35% 的对应水深颜色，岸边和跨水深时分别着色，离水恢复原色。所有经过水面的子弹都有遮罩，水外发射的子弹仍不受阻力；绘制使用共用的小缓冲画布和现有水面图层，遮罩参与世界光照。

水域速度系数按实际轮廓的覆盖面积加权；例如陆地与中水各覆盖一半时为 0.75，浅水与中水各覆盖一半时为 0.625。凹陷空白不计入，重叠复合部件只计一次。地形修正与疾跑、移速增益相乘，不影响转向速度和碰撞推出。圆形玩家通过解析面积计算跨水深减速，统一深度区域直接返回系数；水域三角网格在生成时合并，正常移动不创建覆盖明细，也不运行数值积分。子弹以真实圆形沿路径检测首次命中，拾取和出生校验也使用实际形状。

`new TileMap(width, height, { seed: 8351 })` 可复现基础地形和水域；固定布局测试可用 `{ generateWater: false }` 关闭自动湖泊。`tiles` 存储基础瓦片，生成水域是独立连续图层；`getSpeedFactor(x, y)` 和 `getTerrainCoverage(body)` 会包含该图层，同一瓦片可以返回多个深度的覆盖面积。旧 `WATER / water` 继续表示中水。

角色涉水时，左侧显示竖向排列的三个同色向下折箭头：浅水蓝色、中水紫色、深水红色，仅在水深交界按涉水部分的覆盖比例混色，陆地占比不改变水深颜色。标识约 80 毫秒淡入、离水后 120 毫秒淡出；静止、疾跑或获得移速增益时，仍按地形缓速状态显示。角色模型仅在与水面重叠的部分叠加 35% 的对应水深颜色，跨水深时分别着色，透明像素和陆地部分保持原样。遮罩随朝向、呼吸、相机及震动对齐，并参与世界光照；折箭头在光照之后显示。水深覆盖信息随移动系数在同一次查询中计算，显示复用该结果和缓存水面，渲染不重新求覆盖面积，也不读取画布像素。

开发服务下打开 `/tests/water-fixture.html` 可检查固定种子的完整湖泊，WASD 移动、Shift 疾跑。运行 `npm run test:water-browser` 验收 DPR 1／1.25／2、四档颜色、接缝与曲线滑动；运行 `npm run test:water-performance` 在实际游戏中分别测量 DPR 1／2 下常速、疾跑往返穿越水深边界的表现，每组预热 1 秒并记录 5 秒，移动更新 p95 目标不超过 2 ms。结果保存至 `.review/water-performance.json`，使用相同的浏览器环境变量。

```ts
player.setCollider({ type: "circle", radius: 0.5 });
const body = player.getCollider();
map.isShapeWalkable(body);
map.getTerrainCoverage(body); // 每个地块的 area 和 fraction
map.getShapeSpeedFactor(body);
const result = map.resolveMotion(body, { x: 10, y: 0 }, Math.PI / 4);
// result.collider 为合法姿态；contacts 提供法线、深度及接触点。
// rotationBlocked 表示转向受阻，exhausted 表示求解预算不足，未检查的运动不会提交。
```

通用形状坐标相对实体中心，以 `size` 为一单位；旋转角采用 Canvas 弧度方向。`Entities.setCollider()` 接受多边形和复合体；`Player.setCollider()` 及玩家 JSON 只接受居中圆形。`size` 定义主体尺寸，皮肤和武器的视觉包围盒不得回写主体尺寸，也不得自动生成玩家碰撞体。圆形 JSON 示例见配置说明。

开发服务下打开 `/tests/collision-fixture.html` 可检查单墙、墙角、窄通道、水域和矿石，显示轮廓、接触法线及入水比例。支持 30／60／144 FPS 和 0.5 秒长帧。已有浏览器环境时运行 `npm run test:collision-browser`；`npm run test:browser` 同时运行光照和碰撞浏览器验收，使用相同的 `PLAYWRIGHT_MODULE`、`BROWSER_EXECUTABLE` 和 `TEST_BASE_URL` 环境变量。

这是运动约束系统，不模拟质量、惯性或动态刚体互推。几何接触容差为 0.01 像素；形状由代码／JSON 定义，不从图片提取轮廓，不接受自相交多边形和嵌套复合体。

## 光照与动态投影

环境光是全屏底色（`rgba(214, 226, 240, 0.35)`），决定整张地图的基础明暗；地图左上方外部另有一盏固定弱光，位置为 `(-地图像素宽度, -地图像素高度)`，颜色 `#B4C8E0`、强度 `0.06`，把墙壁和矿石的短影投向右下方，投影长度为瓦片尺寸的 40%，柔边为 4%（当前 20／2 个世界像素）。单位光只照亮地面和水域：锥形手电筒默认 120°／400 世界像素、强度 0.8，脚边另有一圈半径 100、强度 0.5 的小范围全向微光，火把是暖色点光；它们的图层在合成前按地形轮廓裁剪，墙顶和矿石顶面保持环境光亮度，既不会被提亮也不会被压暗。手电筒光束从持灯者身体之外开始（内圈 30 像素），人物不会被自己的光打出高光。距离衰减采用带近场稳定项的平方反比近似，最后 25% 范围平滑归零。

锥形手电筒单独抽成 `ConeLight`，可以复用到其他角色或道具：扇形两条径向边用锥形渐变羽化，弧边沿用半径衰减，亮度低且不会把画面压得比环境光更暗。玩家实例的方向每帧取自身体实际朝向，G 键开关；右键只改变朝向，不影响视野角度和距离。

`lighting.setTerrainLight({ position: { x, y }, color, intensity, shadowLength, softness })` 配置这盏全屏地形光；默认关闭，传入 `null` 关闭。颜色为六位十六进制，强度范围 0–1，长度和柔边使用世界像素。它允许从地图外入射，普通点光源的地图边界遮挡规则保持不变。短影只削弱该光源的贡献，角色光源仍可照亮投影区域。仅查询视口及投影边距内的地形，单个投影缓冲为视口尺寸加柔边，不分配全地图画布；顶部保护与像素边界和角色光照共用。

地图只提取光源附近阻挡地块的外轮廓，忽略内部边。每个圆盘光源采用 8 个固定、对称的采样点，每次先合并投影再平均遮挡率；落在墙内的采样保留其遮挡权重。照明渐变始终以光源中心为基准。遮挡缓冲使用局部半分辨率画布，平均后按 2 倍双线性放大回完整分辨率，不再逐帧做高斯滤波。候选边超过 256 条时降为 4 次采样，低于 192 条后恢复。

遮挡结果按“半径、发光尺寸、采样数、实际轮廓边”的几何哈希缓存，位置单独参与哈希，所以颜色、环境光、相机和亮度变化都不重建；直接修改瓦片数组、破坏矿石这类几何变化一定同帧失效。小发光尺寸的点光（火把）允许在 4 像素内复用上一帧遮挡，抖动不会每帧重新光栅化；超出的位置变化和带测试用大发光尺寸的光源仍然逐帧重建，并给每帧软阴影重建留了固定预算。

柔化后保护墙壁和矿石顶面，单位光的投影作用于地面和水域；其他地形自身继续挡光。设置了 `groundOnly` 的单位光源在地形顶面完全不出力，只有地面和水域收到提亮。地面保护用一张半分辨率的轮廓掩膜完成，不再每帧对累计图层做整屏 `clip`。每个光源先画进半分辨率的局部 scratch 再放大合成，地形光与 `groundOnly` 单位光进入同一张半分辨率累加缓冲，最后一次性放大叠加。实体轮廓绘制与顶面裁剪共用顶点和相机变换，同色地块合并填充，小数相机偏移不会在连续地形之间留下缝隙。最后以 multiply 混合到世界画面，生命和换弹 UI 在光照之后绘制。

```ts
const light = new LightSource(new Vector2(x, y), 500, "#FFF4E8", 1, 16);
const cone = new ConeLight(new Vector2(x, y), 400, "#FFF4E8", .6, Math.PI * 2 / 3, .35);
light.groundOnly = true; cone.groundOnly = true; cone.setInnerRadius(30, 16);
lighting.addLightSource(light);
lighting.addLightSource(cone);
lighting.initialize(canvas.width, canvas.height);
lighting.prepareLightingMask(cameraOffset.x, cameraOffset.y, map);
lighting.applyLighting(ctx);
```

`LightSource` 的第五个参数 `sourceRadius` 默认为 0，兼容原有四参数调用；通过 `getSourceRadius()` / `setSourceRadius(value)` 读取或调整，设为 0 时使用单次硬阴影路径。`groundOnly` 为 true 时光源图层在合成前按地形轮廓裁剪，只照亮地面和水域；游戏里的角色微光、手电筒和火把都开启了它。火把的子弹命中区只有火苗核心（半径 7 世界像素，按子弹半径扩张），并且开火瞬间的准星必须压住火把轮廓（半径 10 世界像素）：两者同时满足，子弹真正穿过火苗才会将其永久熄灭、移除光源并扬起白色烟雾；准星在别处时，子弹只是弹道经过火苗也不算命中，从火把占地内擦过同样不算。`ConeLight` 继承同一套位置、颜色、强度和半径接口，额外提供 `setDirection`、`setAngle`、`setSoftness`、`setInnerRadius` 与 `getStartAngle` / `getEndAngle` / `getFeather`；内圈让光束从持灯者身体之外开始，渲染时由 `LightingSystem` 用锥形渐变裁掉扇形外的光。`TileMap.getShadowEdges(lightX, lightY, radius)` 返回世界坐标线段，`blocksLightAt(x, y)` 查询采样点是否被遮挡。`prepareLightingMask` 的第三个参数可省略，此时仅渲染圆形渐变光。光照画布与主画布使用相同的实际像素尺寸，调用方不要重复乘设备像素比。

战争迷雾由 `VisibilitySystem` 单独负责：以角色为中心的圆形柔边遮罩（半径取自视野，默认 400，外缘柔和过渡 120 世界像素），只裁剪单位层，不参与地形和光照。遮罩完全透明，后续可以整体替换成风格化迷雾后处理。

这是二维顶面约定下的面光源近似，未引入物体高度或完整全局光照；暗部细节来自环境补光。视野用固定锥形手电筒加圆形迷雾，不保存探索记忆。

开发服务下打开 `/tests/lighting-fixture.html` 可以切换硬阴影／自然柔影、调节发光尺寸，检查单块、连续墙、墙角、窄缝、矿石、阶梯和二次遮挡。该页仅用于验收，不进入生产构建入口。

已有 Playwright 环境时，可启动开发服务后运行 `npm run test:browser` 执行全部浏览器验收；只验收光照可运行 `node tests/lighting.browser.mjs`。光照检查覆盖 DPR 1／1.25／2、小数相机偏移、近远半影宽度、地形顶面、多光源、矿石破坏及缓存稳定性。通过 `PLAYWRIGHT_MODULE` 指定现有模块路径、`BROWSER_EXECUTABLE` 指定浏览器路径，`TEST_BASE_URL` 可覆盖默认开发地址；不会为游戏安装浏览器依赖。

`npm run test:terrain-light-browser` 检查新增弱光的暗区亮度预算、短柔影、重叠合并、顶面保护、矿石破坏、屏幕外地形、DPR 和相机偏移、窗口缩放及普通点光源边界规则，并将实际游戏前后对照截图和像素数据保存到 `.review/`。

`npm run test:lighting-performance` 在实际游戏中以 1280×720、一个移动角色光源和一个固定辅助光源测试普通地形、DPR 2 与密集地形。各组预热 1 秒后记录 10 秒，将帧间隔、CPU 提交耗时和截图保存至 `.review/`。默认桌面组检查帧间隔 p95 不超过 16.7 ms；结果仅代表执行机器和浏览器，不包含独立 GPU 计时。

无显示环境的 Chromium 默认走 SwiftShader 软件光栅，单帧光栅化本身就要十几毫秒，帧率门槛在这种环境下没有意义。需要硬件光栅时用 `BROWSER_ARGS` 透传浏览器参数，例如 `BROWSER_ARGS="--enable-gpu --use-angle=d3d11 --ignore-gpu-blocklist"`；`test:water-performance` 的 5 秒采样帧数门槛同理。

## 每帧开销

世界按相机视口绘制到离屏画布，单位层与光效层各自一张同尺寸画布，最后由主画布一次性缩放合成。单位层的合成与迷雾裁剪只处理本帧真正有内容的包围盒；没有金块时整层光效都不创建，清屏、裁剪和叠加全部省掉。迷雾遮罩每帧只清上一帧的区域并填当前圆的外接矩形，渐变范围外本来就是全透明，不必整屏重绘。

粒子保留对象与逐粒 alpha 绘制，但只在对象池里取用、生命周期结束后回池；更新时原地压缩数组，绘制时复用颜色分组、按画布外扩 64 像素剔除，稳态不再为每颗粒子分配向量或选项对象。地图与水域、光源渐变与遮挡、地形光阴影都各自有缓存层；缓存键包含会改变像素的内容或几何，不会把动态状态烘死。`lightingSystem.profiling` 默认关闭，打开后 `profileTimes` 记录 `prepareLightingMask` 的分阶段耗时，仅供排查使用。

## 场景与真实加载

正常流程为菜单 → 图片和配置加载 → 游戏。进度按实际完成的资源项计算，不代表下载字节；加载失败会显示原因并提示刷新页面。没有模拟进度或固定等待。

```ts
const target = new GameScene();
const loading = new LoadingScene(progress => target.load(progress), target);
game.sceneManager.changeScene(loading, 0);
```

`GameScene.load(onProgress?)` 返回 Promise，同一场景的重复调用共用加载任务。`LoadingScene` 接收异步任务和目标场景，不再接收资源映射。退出加载场景后，未完成任务不会触发跳转。

场景切换时调用 `onExit` / `onEnter`。零时长立即切换，过渡中的重复请求被忽略，尚未进入的场景不处理输入。

## 道具与玩家配置

- 新增回血、移速、射速、弹速、伤害五种稀有特殊矿，分别使用对应道具的颜色和图标。地图与水域生成后，每块剩余黄金矿有 5% 概率独立替换为特殊矿，五种等概率，不进行邻接继承；小地图不保证出现。特殊矿耐久均为 100，沿用黄金矿的碰撞、挡光、子弹阻挡、受击高亮与固定累积破损，破损颜色随矿种变化。
- 特殊矿受伤期间不掉物，只有完全击碎才在原矿格中心掉落 1 个对应道具，不掉黄金；直接销毁同样生效，重复攻击不会重复掉落。地面道具不再定时随机生成，矿物掉落不受原先 5 个数量上限及距玩家 200 像素限制，未拾取时持续保留。
- 黄金矿生命 100，普通攻击伤害 10、间隔 0.2 秒。生命降至 90%、70%、50%、30%、10% 时各散落 1 个小金块：第一发命中即有反馈，此后每两发掉落一次；击毁时集中补齐剩余数量，每块矿总计产出 10 黄金。一击跨过多个门槛会补发对应数量，一击击毁直接掉出 10 个。
- 矿块首次受伤生成固定的随机破损图案，以与金块共用的 8×8 世界像素色块表现浅赭金、深金、棕褐和暗褐四档凹陷。当前 50×50 矿块内居中排列 6×6 格，显露数量为 `ceil(损血比例 × 24)`，首次普通命中显露 3 格，最多 24 格；旧色块保持位置与颜色，击毁时清除。破损在受击高亮之后绘制，只影响表面着色。
- 活矿块的金块从朝向玩家的可通行边缘外侧弹出，起点、整条散落路径和落点均检查碰撞，避免进入墙壁、矿石、不可通行水域或越出地图。无安全出口时暂存额度，后续受伤重试，击毁后补齐。人物碰到落地金块自动拾取，每块增加 1 黄金，左上角显示本局累计数量。
- 黄金保留弹跳、破碎碎屑、淡金色呼吸光晕及上浮闪光；少量掉落采用轻量碎屑，击毁采用完整破碎效果。背光短阴影在全部光晕之后合成，只作用于地面，不覆盖墙壁和矿石顶面。
- 移速、射速、弹速、伤害道具各自独立；同类道具替换效果并刷新持续时间，不叠加。
- 回血道具立即恢复 50 点生命，生命范围为 0–100。玩家提供 `getHealth()`、`getMaxHealth()`、`takeDamage(amount)`、`heal(amount)`；当前演示未添加造成玩家伤害的敌人和死亡流程。
- 小鸡中弹后先冒白色气团，约 0.4 秒后掉出肉块；落地即可自动拾取，每块直接恢复 5 点生命（不超过上限），并在角色身边蹦出 `HP+5`，不再计入左上角资源栏。一次同时捡到多块时合并成一条 `HP+N`，拾取音只播一次。
- 伤害增益影响之后发射的子弹，已发射子弹保留创建时伤害。
- 修改 `public/configs/playerConfig.json`、`graphicsConfig.json` 或 `audioConfig.json` 后刷新页面生效，不自动热更新。参数说明见 [CONFIGURATION.md](public/configs/CONFIGURATION.md)。

已有浏览器环境时，运行 `npm run test:mining-browser` 检查矿块累积破损、分阶段掉落、轨迹安全、拾取总量以及实际合成画面的短阴影、相邻光晕和墙壁／矿石顶面保护，覆盖 DPR 1／1.25／2 和小数相机偏移；浏览器路径与开发地址使用前述环境变量。
