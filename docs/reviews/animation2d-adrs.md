# 动画 2D 架构决策记录（ADR）

> 本文记录骨架动画方案审查中必须在开发前定下来的决策。
> 每一条都包含背景、决策、备选与后果，实现时按“决策”执行。
> 状态：已采纳。修订需要同步 `docs/reviews/animation2d-architecture-review.md`。
> 日期：2026-10-31。

## ADR-01：bind 姿态以 Rig 常量为权威

- **背景**：`ROLL_REST_POSE` 与 `drawBody` 的派生规则（髋位置、胸板与背盘半径等）是当前视觉的事实来源，但它们位于 `objects/RollPose.ts` 与 `Player.ts`。若 `PlayerRig` 反向 import 这些文件，`animation2d` 会依赖 `objects`，破坏分层。
- **决策**：`rig/PlayerRig.ts` 自带 bind 常量；用单元测试断言它与 `ROLL_REST_POSE` 及 `drawBody` 派生规则一致。任何一侧改动都会让测试变红。
- **备选**：把常量抽出到 `animation2d` 再由 `RollPose` 引用；或让 `PlayerRig` 直接 import `RollPose`。
- **后果**：多一份常量，但依赖方向干净；单源一致性由测试而非 import 保证。

## ADR-02：瞄准保留橡皮臂，IK 只服务接触

- **背景**：`getNormalPose` 的肘固定在肩手连线上（`NORMAL_ELBOW_T=0.6`），手端点由 `getMuzzlePosition` 决定，并直接约束子弹起点。刚性二骨 IK 会改变肘形或手端点。
- **决策**：瞄准 / 待机继续用程序化“弦上肘”；只有 clip 驱动的接触约束（翻滚支撑手、出拳触点）启用二骨 IK；不可达时回落到弦上肘。
- **备选**：全局 IK；或完全不做 IK。
- **后果**：瞄准手感与弹道完全不变；翻滚的接地感由接触约束提供。IK 代码量更小，收益集中。

## ADR-03：伪高度与阴影走独立视觉通道

- **背景**：现有绘制只有 2D 平面旋转，翻滚没有离地表达；`wadingCanvas` 用 `source-atop` 叠水纹，任何画进缓冲的东西都会被染色。
- **决策**：新增 `altitudePx`（视觉专用，不参与碰撞与命中）；阴影画在 `wadingCanvas` 之外，按高度缩放并降低 alpha；水纹仍只作用于身体。
- **备选**：把阴影画进缓冲；或用全局缩放模拟高度。
- **后果**：翻滚有腾空 / 落地节奏；水深表现不被阴影破坏。碰撞、命中、感知都不受影响。

## ADR-04：部件深度 = 静态层 + 运行时偏移

- **背景**：当前 `drawBody` 用固定 9 步顺序解决遮挡；翻滚中段头 / 胸 / 支撑臂的相对关系会变化，固定顺序不够。
- **决策**：`PartDef.layer` 复现现有顺序；`PartInstance.depth` 允许 clip 与约束按帧给出偏移；渲染器对小数组做稳定排序（不分配）。
- **备选**：完全动态排序；或维持固定顺序。
- **后果**：站立帧与旧版逐像素一致；翻滚可表达正确的穿插。

## ADR-05：视觉朝向用展开角，出场限速

- **背景**：`rollVisualAngle` 用最短弧混合；`weight∈(0,1)` 时若 gameplayFacing 跨 ±π，会跳 `2πw`。同时入场 0.12 s 内完成最大 180° 转向，所需角速度约 26 rad/s。
- **决策**：`visualFacing` 用 unwrap 累加器；翻滚中段锁定翻滚方向；**入场沿用 0.12 s 混合，不设 12 rad/s 上限；出场回正限速 12 rad/s**。
- **备选**：入场也限速（会拉长入场，改变节奏）；或直接复制 gameplayFacing。
- **后果**：跨 ±π 不再跳变；入场节奏保持；出场不会甩头。禁止负 scale 镜像。

## ADR-06：Mixer 推迟到阶段四

- **背景**：方案 §5 在阶段二就引入 Mixer、BoneMask 与 6 层。但阶段二只有翻滚一个 clip，分层要到 punch / hit-react 才有需求。
- **决策**：阶段二只做 `ClipSampler2D` + `PlayerAnimationController` + 事件；阶段四再引入 Mask / additive / 分层。
- **备选**：按原方案提前引入。
- **后果**：阶段二代码量约减半，接口更小；阶段四扩展时 controller 已稳定。

## ADR-07：Legacy 开关只走开发 URL

- **背景**：`parsePlayerConfig` 只接受有限 number，未知键直接抛错；`config-sync.test.mjs` 强制配置组、调试控件、快照三方一致。
- **决策**：`?anim2d=legacy|rig` 仅在开发构建解析；生产默认 rig（阶段三评审后）；阶段五删除 legacy。
- **备选**：新增 JSON 布尔键；或环境变量。
- **后果**：零配置迁移；调试面板不被污染；回滚成本是一次 URL 改动。

## ADR-08：离屏缓冲 extent 取旧公式与 AABB 的较大值

- **背景**：旧 extent `ceil(size*2*(1+3/100)+swayPad*2)+4` 保证现有测试“arc 不出缓冲”；新姿态可能更宽。
- **决策**：`extent = max(旧公式, 内容 AABB + padding)`，只在尺寸变化时重建；测试断言任意相位不出界。
- **备选**：固定放大；或每帧按 AABB 重建。
- **后果**：像素对齐保持；不会因姿态变化裁掉手 / 脚；无每帧扩容开销。

## ADR-09：事件只是信号，粒子与音效仍归玩法

- **背景**：当前尘土在 `requestRoll` 立即生成一次、进度 50% 再生成一次；脚步在 `!isRolling()` 时才发。
- **决策**：动画事件（`rollEntry/rollContact/rollRelease/rollExit/footPlant`）只用于视觉与测试；尘土、脚步、音效的触发点仍由 `Player` 现有代码决定，阶段三最多把“视觉事件”与“玩法粒子”对齐，不改变时机。
- **备选**：让动画事件接管粒子。
- **后果**：玩法行为零变化；动画与粒子可能仍有 1 帧差异，可接受。

## ADR-10：玩法发射点冻结，视觉 socket 只做表现

- **背景**：`shootAt` 先写 `armAngle/armDistance/armLift`，再取 `getMuzzlePosition` 作为子弹起点，并补偿散布；枪口火焰也用同一位置。
- **决策**：阶段一至四 `getMuzzlePosition` 保持唯一的子弹起点；视觉 socket 只用于武器绘制与（阶段五验证后）火焰锚点；验证阈值 ≤1 px。
- **备选**：让 socket 成为发射点。
- **后果**：弹道、散布补偿、命中判定不变；视觉与玩法可以在阶段五安全合流。

## ADR-11：翻滚接触与重心的数值边界

- **背景**：无边界约束的 COM / 高度曲线会让角色“穿地”或“漂浮”，也会让手部锚点拉断手臂。
- **决策**：`altitudePx ≤ 0.18×size`；`comOffsetPx ≤ 0.12×size`；支撑手 / 脚释放阈值按距离（建议 0.1×size）；手部漂移 ≤2 px；不可达即回落。
- **备选**：只按时间释放；或不设上限。
- **后果**：姿态始终可信；参数可调但有硬边界，方便测试与评审。

## ADR-12：测试迁移采用“录制 + 对照”，不 mock Canvas

- **背景**：`roll.test.mjs`、`run-sway.test.mjs` 通过 mock `wadingCanvas` 与记录 arc / rotate / scale 来断言绘制；这会把实现细节钉死。
- **决策**：阶段一引入 `DrawCommandList`；legacy 默认期间现有测试不改；新渲染器测试断言命令序列；阶段三重写绘制断言时以命令层为准。
- **备选**：继续 mock；或只做像素测试。
- **后果**：测试更稳定，失败信息更可读；阶段三的测试重写需要在 PR 中显式列出。

## ADR-13：Down / GetUp / Climb 移出动画范围

- **背景**：当前玩法没有倒地、起身、攀爬状态；动画若自造这些状态，会与碰撞、输入、感知冲突。
- **决策**：本方案不做这三个动作；阶段五只做视觉级受击晃动。若未来要倒地，先补玩法契约，再回来加 clip。
- **备选**：动画先行，玩法后补。
- **后果**：避免“动画能穿墙 / 倒地但还能开枪”的假状态；范围更可控。

## ADR-14：动画配置在阶段五之后再考虑曝光

- **背景**：新增配置键要同步 `PlayerConfig`、`debugSchema`、`getConfigSnapshot` 与 `config-sync` 测试；阶段一至四的数值还在调整。
- **决策**：阶段一至四不新增 JSON 配置键；阶段五若确认要暴露（如 `altitudeScale`），再一次性补全三处与测试。
- **备选**：现在就加，便于调参。
- **后果**：调参靠常量与开发工具；配置面稳定；不会因未校验字段破坏启动流程。
