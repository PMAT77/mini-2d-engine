# 顶部昼夜时钟 HUD

## 审查与接入决策

本次工作开始时，工作区已经包含未提交的 P1 战役状态、时钟、两地点切换和临时 CampaignHud。此次在这些接口上接入 UI，不创建或修改第二套世界时间。

- `GameScene.draw` 的世界合成后、其他屏幕 HUD 前是读取状态的插入点；放在背包隐藏分支之外。
- 原主画布位于 DOM 背包、暂停遮罩下面。新组件使用独立、透明、`pointer-events:none` 的 Canvas 层，仍由同一场景绘制调用驱动，不启动 rAF、定时器或输入监听。
- `WeaponBrushTexture` 的多笔触轮廓、缺口、纤维和 DPR 缓存可以复用。增加可选 `charcoal` 墨色和细纤维；既有调用默认仍使用原武器色，不改武器素材或布局。
- 现有临时 CampaignHud 占用了顶部中央。移除它的可见时间行和矩形卡片，只保留轻量旅行/结束白天按钮，跟随新时钟下缘；保留原时间文本查询和无障碍接口。
- 小地图、黄金/积分、右上调试按钮默认位置及右侧武器区作为占位传入。只改变新时钟的布局，不修改原 HUD 的布局计算。
- 桌面为 500×144 CSS px，顶部 12px。宽度不足时缩放；极窄屏在小地图和黄金/积分下方居中，使用两行紧凑版。紧凑版只保留日期、阶段图标、时间及关键提示。打开背包时在顶部使用紧凑版，避开原背包标签。
- CSS 布局直接使用视口逻辑尺寸，避免 1.25 DPR 下画布整数像素取整导致居中偏移。文字和矢量按实际 DPR 绘制，笔刷沿用现有最高 2 倍纹理缓存。

## 关键接口

```ts
interface DayClockHudState {
  worldMinute: number;
  location: 'field' | 'camp';
  raid?: { wave: number; totalWaves: number };
}
```

正常运行时，`worldMinute` 来自 `CampaignSession.getClockReading()`，地点来自当前场景。`getDayClockView` 复用 `readGameTime`，不接受独立天数、时刻和阶段，因此这些字段不会出现不同步。HUD 不推进会话，不持有累计时间，不读取墙上时间。

`getDayClockHudLayout(width, height, reserved, forceCompact)` 返回 CSS 像素矩形和设计缩放；DPR 只影响 backing canvas 和笔刷纹理。`drawDayClockHud(ctx, state, layout, dpr)` 是可独立调用的绘制接口，原点由调用方设置；`DayClockHud.draw` 管理屏幕定位和透明画布。

生存日从 06:00 开始。进度为 `(worldMinute % 1440) / 1440`，18:00 刻度是 50%，20:00 是 58.333…%，三段比例为 12:2:10。时刻只取整数分钟显示，指示器保留小数分钟；倒计时向上取整，截止前不会提前显示 00:00。换日和阶段沿用现有 GameClock，没有额外 UI 换日事件。

日期至少两位补零，三位数自然扩展，极长日期只在左侧固定区域缩字。时钟的五个字符逐个绘制在固定槽位，数字宽度和字体回退不会改变槽位位置。返程前最后一小时的提示逐渐变暖；本次不增加可选的呼吸动画，暂停时像素完全静止。

`attach` 幂等，`dispose` 删除整个组件根节点。组件没有全局监听器；场景挂起、切换失败回退、恢复和退出复用现有生命周期。死亡时隐藏时间，正常暂停继续显示相同读数。

## 验证

- 单元测试：06:00/18:00/20:00/次日 06:00，午夜所属生存日，真实时间比例及小数指示位置，99→100 天，固定字符槽位，野外/营地提示，倒计时、逐渐警示色、不同布局、暂停和背包紧凑版。
- 新浏览器测试：1440×900、1100×800、800×600、640×360、390×844、320×568；DPR 1、1.25、2、3。检查逻辑尺寸、居中、默认小地图/调试按钮避让、backing pixels、正常及野外背包、暂停、旅行、死亡、挂起/恢复、退出清理。
- 数字绘制检查记录实际 Canvas 调用，比较 11:11 和 23:59 的全部字符坐标。
- 同一场景注入不同只读 HUD 状态时，对比主游戏画布完整像素；白昼、紧急、黄昏、夜间、错过返程、第 100 天全部一致。新层不改动世界、武器、生存、快捷栏及其他 Canvas HUD。
- 运行命令与最终结果见本报告末尾。

浏览器脚本沿用项目既有 Playwright 环境变量，不给项目增加依赖。`TEST_BASE_URL` 默认 `http://127.0.0.1:5182/`；先启动 Vite。截图输出到 `.review/day-clock/`，可用 `SCREENSHOT_DIR` 覆盖。

## 已知边界与 P4 / P5

- 当前 P1–P3 的 `PrototypeNight` 在 20:00 自动跳到次日 06:00。此次保留该行为，因此正常战役目前不会停留在夜间；没有为视觉验收更改世界时间或夜袭规则。
- P4 接入真实夜袭时，将实际波次传入 `DayClockHudState.raid`；未提供波次时显示“夜间防守时间”，不会捏造正在进行的袭击。时钟和日期始终保留。实际夜袭状态应由统一战役读模型提供。
- P5 继续由战役/远征协调器管理 18:00 截止、错过返程和跨日后果。HUD 当前只按地点与阶段显示提示，不执行强制撤离、处罚、跳时或死亡恢复。
- 320px 窄屏会将新时钟放在原小地图和积分下方，且与武器区之间留隙；这是为保持既有 HUD 位置作出的紧凑布局。背包打开时新时钟回到顶部，不更改背包本身。
- 低于 360px 时，临时战役操作按钮保留在原有右上窄屏通道中，避免时钟下方的按钮挤入武器区。
- 调试按钮可被玩家手动拖动；默认位置有避让。此任务没有修改该按钮的拖动功能。
