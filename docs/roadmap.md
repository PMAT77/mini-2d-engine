# 开发路线图

本文把 [游戏设计](game-design.md) 落到现有代码上。现状以 2026-10-30 的仓库为准。

## 1. 现状盘点

| 能力 | 现状 | 主要代码 |
| --- | --- | --- |
| 地形与碰撞 | 随机瓦片地图、水域、墙体、矿石、贴墙滑动 | `src/map/`、`src/physics/` |
| 动态光照 | 环境光、地形光、手电锥光、火把、软阴影 | `src/core/LightingSystem.ts` |
| 玩家视野 | 锥形视野、迷雾、三层感知（隐藏／轮廓／识别） | `src/vision/` |
| 声音 | 播放、距离衰减、循环淡入淡出 | `src/core/SoundPlayer.ts`、`src/scenes/GameScene.ts` |
| 角色 | 移动、疾跑、体力、翻滚、主副武器 | `src/objects/Player.ts` |
| 战斗 | 弹道、散布、后坐力、弹坑 | `src/objects/Bullet.ts`、`src/objects/CraterSystem.ts` |
| 交互物 | 金块、肉块、火把、可破坏矿石 | `src/objects/` |
| 敌人 | 只有小鸡：游荡、受惊、一击必杀 | `src/objects/Chicken.ts` |
| 局内目标 | 无 | — |
| 背包 | 无 | — |
| 撤离 | 无 | — |
| 局外成长 | 无 | — |

结论：视听表现与移动手感够用，缺的是「局」，也就是目标、威胁、取舍与结算。

两套素材可以直接支撑后续开发：

- `public/audio/footsteps`：15 种表面、103 段单次采样，可直接做成地形材质噪声表。
- `public/assets/images/ui/keyboard-mouse`：124 个键鼠图标，可用于交互提示。

## 2. 差距清单

按依赖顺序排列：

1. 噪声事件总线：把世界里的声音变成可查询的数据。
2. 敌人感知：视觉（复用视线与光照查询）加听觉（订阅噪声），再加记忆。
3. 敌人行为：巡逻、怀疑、搜索、攻击、呼叫增援。
4. 寻路：瓦片网格上的 A*。
5. 局内状态机：进入、搜刮、警戒、撤离、结算。
6. 背包与战利品：格子、价值、重量。
7. 撤离交互与结算界面。
8. 程序化站点，可后置。
9. 存档与元循环，可后置。

## 3. 里程碑

### M0 定位与设计

产出：本文、[游戏设计](game-design.md)、[规则与数值](rules.md)、[内容设计](content.md)，以及 README 的定位段落。

验收：定位、支柱、核心循环三段能被一句话复述。规则与内容两份文档能直接支撑 M1 的数值配置。

### M1 垂直切片：带着一件东西活着出去

范围：

- 1 张手工小图，约 40×30 格，3 个房间加 1 个撤离点。
- 1 种巡逻敌人，具备视锥、听觉、怀疑、搜索与攻击。
- 噪声事件总线，以及世界内的声波可视化。
- 4 类噪声：走、跑、涉水、开枪。
- 光照影响被发现距离。
- 撤离点 6 秒交互，加成功／失败结算。
- 3 种战利品，加 6 格背包。

验收：

- 一局 3～5 分钟，能完整走完进入、搜刮、撤离、结算。
- 关灯绕背可行，开枪必然引来附近敌人。
- 撤离成功与失败都有明确结算。
- 噪声传播、敌人怀疑值、撤离状态机有单元测试。
- `npm test`、`npm run typecheck`、`npm run build` 通过。

### M2 系统深度

- 地形材质噪声表：金属、玻璃、木板、草地、水。
- 可破坏墙与门，破门有噪声与耗时。
- 诱饵：石子、录音机、照明棒。
- 警戒等级与增援波。
- 敌人扩到 3 种：巡逻兵、猎犬、探照灯。

### M3 程序化站点

- 房间模板、连接图与战利品预算。
- 撤离点规则：1 个明点加 1 个条件点。
- 危险度曲线：时间加搜刮量。
- 保证每条种子至少有 1 条低交火路线。

### M4 元循环

- 仓库、出售、蓝图、干员。
- 本地存档，使用 localStorage。
- 失败惩罚与难度解锁。

### M5 打磨

- 音频层次：环境、威胁、反馈。
- 新手引导与提示。
- 平衡、可访问性与性能回归。

## 4. 技术方案

### 新增模块

- `src/ai/`：敌人感知、行为状态机、寻路。
- `src/sim/`：噪声总线、光照查询封装、可见性查询。
- `src/run/`：局内状态机、撤离、结算。
- `src/inventory/`：背包与战利品。

### 复用现有能力

- 视线与遮挡：`src/vision/SightGeometry.ts` 的 `hasLineOfSight` 已经与渲染解耦。
- 光照强度：`src/vision/IlluminationProbe.ts` 的 `illuminationStrengthAt` 可以直接给 AI 使用。
- 多观察者：`PerceptionSystem` 从第一天就支持多个 observer，敌人可以作为 observer 接入。
- 声音播放：`SoundPlayer` 只负责播放，传播逻辑放进新的噪声总线，两者解耦。

### 关键实现顺序

1. `NoiseBus` 与事件定义。
2. 敌人基类与感知组件。
3. 巡逻、怀疑、搜索状态机。
4. A* 寻路。
5. `RunState` 与撤离。
6. 背包与结算界面。

## 5. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 光照系统性能 | 敌人变多后帧率下降 | 复用现有性能测试，限制实时阴影数量 |
| 潜行与枪战失衡 | 要么全程潜行，要么全程突突 | 用「开枪引来增援」强制节奏切换 |
| 程序化地图不可读 | 玩家迷路，体验变差 | M1 先做手工图，M3 再程序化 |
| 范围膨胀 | 做不完 | 把非目标清单写进设计文档，评审时逐条对照 |

## 6. 下一步

建议从 M1 开始，先做噪声总线与敌人感知，再做撤离，最后接背包与结算。
